# Contributing to zer0-CMS

Thanks for wanting to help.

## Getting set up

```bash
npm install
npm run compile   # type-check + lint + all five bundles
npm run watch     # then press F5 in VS Code to launch the Extension Host
npm test          # unit + golden + MCP stdio + integration
```

The Ruby half needs nothing installed — it is stdlib-only:

```bash
cd rails && ruby -Ilib test/zer0_cms/test_abc_engine.rb
```

## The rules that are not negotiable

These are enforced by the build, so you will find out quickly, but knowing them up front saves a round trip.

1. **`src/core/` and `src/mcp/` must not import `vscode`.** They are pure Node. eslint blocks the import, and the MCP bundle — which marks nothing external — turns it into a build error. If core needs something from the editor, take it as a parameter or an injected callback.
2. **No runtime dependencies.** The extension ships with an empty `dependencies` block and that is a feature: this tool holds a publish gate. `@anthropic-ai/claude-agent-sdk` is the single exception, and it is *optional*, dynamically imported, and off by default. Hand-roll the rest against Node's stdlib.
3. **No `innerHTML` in `src/webview/`.** Build DOM with `el()` and assign text with `textContent`. Content comes from user files; the CSP is a second line of defence, not the first.
4. **No `any`, no `@ts-ignore`, no empty `catch {}`.** If you must swallow an error, say why in a comment and return a fallback.
5. **The webview is UI, never the gate.** A button posts an intent and a target. Every check — publish-allow, brand guard, ledger, draft status, required fields — is re-run host-side in the same function the command palette calls. A check that exists only in a webview is decoration.

## Style

- **Conventional Commits**: `type(scope): description` — `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`.
- Branch from `main` and open a PR. Never push to `main`.
- **README-First, README-Last**: read the nearest `README.md` before changing a directory, and update it after.
- One paragraph per line in markdown — CI enforces it (`tools/unwrap-prose.py`).
- Every source file opens with a short block comment saying what it is and why it exists.

## Tests

- `src/core/**` is covered by plain unit tests that need no extension host.
- `src/test/fixtures/golden/**` holds cross-lane fixtures generated by the Python publishing lane. The ledger bytes, publish previews and worklists must match it byte-for-byte, because both lanes write the same files in the same repos. **Regenerate goldens with `generate.py`; never hand-edit one to make a test pass.** If a golden test fails, decide first whether the bug is in our serializer.

## Where things live

| Path | |
|---|---|
| `src/core/` | The domain. Pure Node, fully testable. |
| `src/mcp/` | The standalone MCP server. |
| `src/webview/` | Vanilla TS + CSS UI for the panel, dashboard and agent. |
| `src/` (top level) | The thin `vscode` shell: activation, commands, views, providers. |
| `media/` | Stylesheets and branding. |
| `schemas/` | The JSON Schema for `zer0.json`. |
| `rails/` | The ABC content engine — a separate product in the same repo. |

## Reporting things

Bugs and feature requests: <https://github.com/bamr87/zer0-CMS/issues>. A small reproduction — a `zer0.json` and one content file — is worth more than a long description.
