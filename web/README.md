# `web/` — the React frontend

The one web frontend of zer0-CMS ([ADR 0006](../docs/adr/0006-one-python-platform.md) decisions 2 and 9; [`TARGET.md`](../docs/plan/TARGET.md) § The studio): the **studio**, where people write, create and review content, follow agent runs and work with the AI content layer (assistants, pipelines, output schemas, briefs, conversations, providers and models), and the **shared packages** its workspaces are built from — which the VS Code extension's webviews will render as they are (PLAN G10), so a studio capability reaches the extension by construction. It talks to the platform (`content/`) only through the platform's API, through a client generated from the committed OpenAPI document. PLAN P4 built it; the site renderer (`web/site/`, PLAN P6) joins it later.

## Layout

## Commands

```bash
cd web
npm ci                 # the committed lockfile
npm run dev            # http://localhost:5173/studio/ against PLATFORM_URL (default http://127.0.0.1:8000)
npm run lint           # ESLint, including the @zer0/ui host gate below
npm run typecheck      # tsc --noEmit over every package, the studio and the tests
npm test               # Vitest + Testing Library, in jsdom; nothing reaches a network
npm run build          # studio/dist/, asset URLs under /static/studio/
npm run gen            # regenerate @zer0/api's types after the platform's API changed
npm run check:api      # fail when the committed types differ from a fresh generation
```

The API changes in the platform first: change a view or serializer in `content/api/`, regenerate the document (`cd content && python manage.py spectacular --format openapi-json --urlconf ops.openapi --fail-on-warn --file ../schemas/openapi/openapi.json`), then `npm run gen` here. CI (`web.yml`) runs `check:api` on every change to `web/` or to the document, so a client and the API it calls cannot drift apart.

For a local studio with something in it: `cd content && python manage.py migrate && python manage.py seed_demo && python manage.py runserver`, then `npm run dev` here, and sign in as `editor` with the password `zer0-demo` (the default only under `DEBUG`). `seed_demo` makes a demo site with an article, a draft and an SEO agent's pending suggestions.

## How the studio meets the platform

**One origin.** The platform serves the built studio at `/studio/` (`content/api/studio.py`): its assets are static files under `/static/studio/` (collected from `studio/dist/`, which settings add to `STATICFILES_DIRS`), and every other `/studio/` path answers `index.html`, so the studio's router owns them. The session cookie and the CSRF token need no CORS. In development Vite proxies `/api`, `/admin` and `/static` to the platform instead. The platform image builds the studio in a Node stage (`content/Dockerfile`) and copies only `studio/dist/`.

**Signing in** goes through `studio/src/auth.tsx` and nothing else: `GET /api/v2/me`, `POST /api/v2/session/login` and `/logout` (`content/api/session.py`). PLAN G3 replaces those three calls with django-allauth's headless API in that one file.

**An enforced CSP.** The page `/studio/` serves carries a Content-Security-Policy with a nonce made per request: scripts only from the platform, no inline style except the `<style>` elements Mantine writes, which carry the nonce (Vite writes a placeholder into `<meta property="csp-nonce">`, the platform replaces it, `main.tsx` hands it to Mantine, and to `get-nonce` for the `<style>` that a modal's or a drawer's scroll lock writes through `react-style-singleton`). TipTap runs with its injected CSS off; `@zer0/ui/ui.css` carries what ProseMirror needs. A Mantine `Drawer` or `Modal` runs with `lockScroll={false}`: its scroll lock writes a `<style>` element of its own, without the nonce, which the policy refuses. The extension's webviews need the same policy, so the studio is held to it from the start; the browser scenarios fail on any console error, a CSP violation included.

## The host contract — why the packages can go into a webview

`@zer0/ui` never builds a client, opens a stream, reads a URL, a cookie or storage, or imports a router. A host wraps it in `<StudioProvider api stream go>`: `api` is an `openapi-fetch` client (the studio's speaks same-origin HTTP; the extension's will speak `postMessage`), `stream` opens a server-sent event stream (the studio uses `EventSource` on `/api/v2/agent-runs/<id>/stream/`, and reports a stream the browser gave up on as the event `error`), and `go` turns a `Destination` (`{to: 'page', id}`, `{to: 'run', id}`, `{to: 'review', runId}`, `{to: 'story', id}` …) into a route or a panel — the studio gives a story's panel its own address, `/studio/newsroom/stories/<id>`. ESLint enforces it for `packages/ui/src/**`: no `react-router` or `openapi-fetch` import, no `fetch`, `EventSource`, `XMLHttpRequest`, `WebSocket`, storage, `location` or `history` global, no `window.location` or `document.cookie`, no `dangerouslySetInnerHTML`.

## Rules the code keeps

- **The editor never rewrites what nobody touched.** A `markdown` block is kept verbatim by the platform, so `RichText` opens a block in TipTap only when TipTap writes it back unchanged (`roundTrips`); anything else — Liquid, raw HTML, a list written with `*` — opens as source. Saving sends only the fields that changed, the body only if it changed, and the revision it was edited from, so the platform refuses a save over someone else's newer revision (409) rather than replacing it. Blocks keep their ids, so suggestions and provenance still find them; a block added in this session is keyed by a client key that follows it through edits, moves and removals, never by its position, because TipTap reads a block's content once. A `paragraph` block arrives in Wagtail's database format (internal links as `linktype`/`id`), which TipTap cannot hold, so it opens as source and goes back in that format.
- **Nothing publishes except the publish buttons.** Save is a draft revision; accepting a suggestion or reverting is a draft revision; publish, schedule (a time to go live, a time to come down, or both) and unpublish are separate calls, each re-checked by the platform against the person's Wagtail permissions.
- **A lock is shown, not worked around.** A page a Wagtail lock keeps from the person (`page.lock`: someone else's, a workflow task's, a scheduled publish's) opens read-only with the lock's own sentence; the platform refuses every write anyway (409 `resource.locked`), and cancelling a schedule is the one action left.
- **"Accept all" is all that is shown.** Accepting a run's suggestions sends the ids of the ones the inbox shows (stale ones left out), so a view filtered to one page, one site or the first hundred never accepts what nobody saw.
- **A live timeline survives its stream.** The run stream ends at the run's final status or at the server's time limit; `RunTimeline` stops on a final `status`, reopens a live run's stream after a pause, and backs off (1 s, 2 s, 4 s … up to 30 s) from a stream that broke.
- **Fields come from the platform.** `FieldsPanel` renders the specs each page carries (`field_specs`: name, label, group, kind, choices), so a new field or page type needs no change here.
- **Every AI result is something a person reviews.** A brief is applied as a new draft whose text waits as suggestions; the editor's AI panel asks for its answer as suggestions on the open page (the whole page, one block, or text selected in a block as saved — `run/` with `suggest`); a conversation's answer is read, asked again or promoted to a brief. Nothing an assistant writes is saved or published by the studio.
- **A selection is sent with where it is.** The AI panel sends the field of a structured block it is in (each field's input carries `data-field`) and the character it starts at, in code points, in the text a person sees: a field's own selection says where; a paragraph's source is HTML, so the place is counted in its readable text (`DOMParser`); in the rich editor it is counted in what TipTap shows — exact for a paragraph, and for Markdown only when the words show as often as they are written (else the platform takes a selection that appears once and refuses the rest with a reason). The platform swaps that text and nothing else.
- **A run is followed, never awaited.** Anything that reaches a model answers `202` with a run; the screen that started it shows `RunProgress` (`useLiveRun`, the run timeline's following) and reads what the run produced — the brief, the messages, the answer, the provider's health — once it is final.
- **One request per action.** Every request that starts a run carries an `Idempotency-Key` made when the person acts (`newKey`, kept in the mutation's variables), so a repeat of that request replays the first run; its control waits while the request is out (and Ctrl+Enter with it); and a button that starts a run or makes a row ignores the second click of a double click (`oneClick`), however fast the platform answered the first. Saving a brief and generating it are two requests: a new brief is made once and opened whatever generating it answers, and every screen shows the latest request to generate a brief (`useMutationState`). A conversation opens on its newest messages and loads earlier ones on request (`useInfiniteQuery`, `ordering=-seq`), reading again only the pages it shows.
- **A credential only goes in.** The provider form's credential field starts empty every time, sends a value only when one is typed (or an empty one when removing is asked for), and shows the stored one only as set or not set; the platform never returns it.
- **Less code.** Mantine for every control, TanStack Query for every request and cache, TipTap and `@mantine/tiptap` for rich text, jsdiff for diffs, `openapi-typescript` + `openapi-fetch` for the client. A workspace adds a component to `@zer0/ui` and a route to `studio/src/App.tsx`; an area that is not built yet already has its place in the navigation, naming its milestone.

## Libraries and versions

React 19, React Router 7 (the version TARGET.md names; 8 exists, and moving is a later, deliberate change), TanStack Query 5, Mantine 9 with `@mantine/tiptap`, TipTap 3 with `@tiptap/markdown` (also read-only, to render an answer's Markdown without injected HTML), jsdiff, `get-nonce` (the studio host only), `@dnd-kit/core` and `@dnd-kit/sortable` (a pipeline's steps, dragged with the pointer or the keyboard), `openapi-typescript` + `openapi-fetch`, Vite 8, Vitest 5 with Testing Library and jsdom, ESLint 10 with `typescript-eslint`, TypeScript 5.9 (`typescript-eslint` and `openapi-typescript` do not accept 6 yet). CI runs Node 24; jsdom needs Node 22.22 or newer.

**The lockfile is committed and `openapi-typescript` is pinned exactly** — a deviation from the hub's always-latest posture, recorded in [`AGENTS.md`](../AGENTS.md) § Standard deviations: the committed `schema.d.ts` is that generator's output, so a floating generator would fail the drift check for no change of the API, and `npm ci` in CI and in the image needs the lockfile.
