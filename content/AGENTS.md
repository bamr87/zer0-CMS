# AGENTS.md — the content plane (`content/`)

Guidance for AI coding agents working in `content/`, the Django + Wagtail content plane. The repository-wide rules — the plane boundary, the agent safety rules, the workflow — are in the root [`AGENTS.md`](../AGENTS.md); this file adds what holds inside this project. [`README.md`](README.md) maps the apps; ADR 0001 says why they exist.

"Done" for a change here means `python -m pytest -q` (with `-m "not slow"` as the fast loop) and `python manage.py makemigrations --check --dry-run` pass, `ruff check . && ruff format --check .` are clean, `python manage.py run_evals --all --recorded` passes, and the three committed schemas are current: `schemas/graphql/schema.graphql` (`manage.py graphql_schema --out …`), `schemas/content/ai-schema.json` (`manage.py wagtail_ai_schema --out …`) and `schemas/openapi/openapi.json` (`manage.py spectacular --format openapi-json --urlconf ops.openapi --fail-on-warn --file …`). CI runs the suite on SQLite and on Postgres with pgvector (`content.yml`).

## Invariants

- **Every content change goes through the registry or the accept flow.** A tool is the only way an agent touches content (`agents/registry.py`), and `suggestions.services.accept` is the only way a suggestion becomes a revision. Both call `cms.services.save_draft` / `publish`, which run in one transaction. Never add a second path that writes pages for an agent, and never call a tool function directly from a surface — call `registry.call`.
- **The studio's endpoints serve people, through the same services.** `api/pages.py`, `api/review.py` and `api/session.py` refuse agent principals (`IsPerson`), check Wagtail page permissions in `cms.services` and `suggestions.services`, and never publish except from the publish and schedule endpoints: a save, an accepted suggestion and a revert are each a draft revision. A save must name the revision it was edited from (`null` only for a page without one) and is refused (409) when a newer one exists; a block the person did not change is stored as it was, never re-cleaned, and two blocks never share an id. A shape the studio reads is a serializer in `api/serializers.py`, so the OpenAPI document and `web/packages/api`'s generated client follow it (`cd web && npm run gen` after regenerating the document).
- **Finding a page is not opening it.** A person finds the pages Wagtail's explorer would show them (`cms.services.visible_pages`: those they hold a permission on, the ancestors that lead there, platform page types only); opening one — its draft, fields, blocks, revisions — needs the right to edit or publish it, as Wagtail's own draft view does, and anything else is a 404.
- **Every page writer starts with `cms.services.writable`.** It takes the page row's lock for the transaction, so two writers that start from the same revision run one after the other (a second save is then stale; a second accept builds on the first's revision), and it refuses a page a Wagtail lock keeps from the person — another person's, a workflow task's, or a scheduled publish's — with `PageLocked` (409 `resource.locked`). Cancelling a schedule is the one change a scheduled page's lock allows.
- **One scope per model.** `Suggestion.objects.visible_to(user, site=None)` and `AgentRun.objects.visible_to(user)` are how every view, resolver and service reads those rows (a reviewer may open the run behind what they may decide); a refusal never names what the person cannot see — a 404 for an invisible row, and `PermissionDenied` messages without the target's title.
- **Rich text travels in Wagtail's database format** (`<a linktype="page" id="…">`), the form every reader of a page gets; `suggestions.services.clean_block` expands it to the editor's form before the whitelist, so a link or embed the block's features allow keeps its target.
- **Tools declare an effect and run as an agent user.** `read`, `propose`, `write`, `publish`; the registry checks the narrower of the agent's and the page's policy, the agent's tools list (and the token's), the principal (`agent:<slug>`, active, never staff or superuser), Wagtail permissions as that user — and, when the call acts for a person (`ToolContext.on_behalf_of`: a run whose prompt and tools a person chose), that person's edit right on the page too — and the rate. A review agent never gets a `publish` tool. A new tool needs an input schema with `additionalProperties: false` (`obj()`), and the cheapest effect that is true.
- **Agents start at `suggest`; promotion is earned.** A definition goes live only through `AgentDefinition.publish()`, which runs the eval gate; raising the policy also needs the accept rate. Change an agent by editing `agents/definitions/<slug>.yaml`, never by setting `live` or `policy` on a row.
- **One way to reach a model.** Only `ai/providers/` imports a provider SDK (`anthropic`, `openai`, `litellm`, `claude_agent_sdk`), each inside its adapter; everything else asks the registry (`ai.providers.get`), and `tests/ai/test_providers.py` fails on an import anywhere else. Every AI generation a person asks for is a run of the `assistant` agent through `ai/services.py` — never a provider call inside a request — and the worker re-checks what the run uses (the rows, against its starter; the provider, enabled and in budget), since a run can start from more than one surface.
- **Tests never call a model.** Use `FakeLLM` in unit tests and recordings (`agents/recordings/`, placeholders instead of ids) for eval scenarios. A prompt change makes its recordings stale on purpose: re-record, don't loosen the digest check.
- **One revision per accepted outcome.** Accept a run's suggestions together; a tool that writes (`content.draft_revision`) writes one revision for all its ops. Intermediate work lives in `AgentStep` rows, not in revisions.
- **An event is emitted in the transaction that made the change.** `outbox.services.emit` refuses otherwise. A new event type is a schema in `schemas/events/` (and an example) first, with contract tests on both planes; a breaking change is a new version.
- **Agent review is never a workflow's last task.** Approving the last task publishes the page as the approver, and an agent never publishes; `AgentReviewTask` rejects with that reason when it is last.
- **Order-preserving JSON where order is content.** `BasePage.front_matter` is an `OrderedJSONField` because Postgres `jsonb` sorts keys; use it for any JSON whose key order a person wrote.
- **The Jekyll bridge is exact.** An unchanged page exports its stored source byte for byte; a changed page renders typed fields over its original front matter (dates stay the original string unless the date changed). An importer never overwrites what was changed here — a page an editor changed in Wagtail, an AI row a person changed or deleted (`importers.models.ImportedRecord`) — `--force` aside. `test_the_real_sites_round_trip_byte_for_byte` holds every site in this repository to that.
- **Vectors live in `graph.Embedding`, never on a page row** (a revision would copy them), keyed by model and content hash.
- **Vendored here:** `agents/data/abc_lexicons/*.yml` are byte-identical copies of `rails/lib/zer0_cms/abc/lexicons/*.yml`, declared in the root `workspace.yml`. Edit the source and run `bin/zer0 vendor --write`.
- **Every non-2xx is the envelope.** A REST view raises `ops.errors.ApiError` (or `Invalid`, `Forbidden`, `NotFound`, `Conflict`, `Locked`, `Unavailable`) or a DRF exception and never returns `Response({"error": …})`; a GraphQL resolver raises `GraphQLError` for an error the client should read; MCP keeps JSON-RPC errors. `/healthz` touches nothing — a probe view is `non_atomic_requests` and never reads the database; what needs a dependency belongs in `/readyz`'s checks (`ops/README.md`).
- **The web role serves on threads.** gunicorn reads `gunicorn.conf.py` (gthread workers): a run's event stream holds its request for minutes, and a sync worker is killed at its timeout mid-stream. A stream opens with a comment frame and sends one when quiet.
- **Nothing logs a secret.** Log through `logging` (the handler redacts token shapes — an agent's `zer0_…`, a person's `zer0u_…`, the fleet's — and `Authorization` values); never print a token, and never put one in an exception message that a `500` could carry — the envelope hides the message, the log does not. Django's error reports (`ops.logging.ExceptionReporterFilter`, on in development too) and Sentry's events (`ops.sentry`) redact the same shapes in every frame's variables; mark a local that holds a credential `@sensitive_variables`.
- **Authenticating writes nothing in the request.** Both bearer tokens are `accounts.tokens.HashedToken`: a hash, a raw token shown once, and a use recorded at most every five minutes after the request commits — a write inside `ATOMIC_REQUESTS` locked the database for every parallel request a client sends. A person's token is issued, listed and revoked through `accounts.services` (90 days by default; a superuser's only on purpose).

## Conventions

- Every module opens with a docstring saying what it is and why it exists; every app has the README its code points to.
- Ruff is the linter and formatter (`pyproject.toml`); no blind `except` without a comment saying why, no `# type: ignore`.
- Migrations are generated (`makemigrations`), never hand-written, except the pgvector extension step in `graph/migrations/0001_initial.py`.
