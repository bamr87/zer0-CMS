# `graph/` — the content graph

> The content graph: structural, agent and behavioural edges, the vectors beside them in Postgres, and the retrieval built on them.

Entities, edges and vectors in Postgres (note §5), and the retrieval built on them.

- **Structural edges come free.** On every publish, `index_page` rebuilds the page's `child_of`, `references` (Wagtail's `ReferenceIndex`: chooser blocks, foreign keys), `links_to` (Markdown links and Obsidian wikilinks resolved by permalink, URL or source path), `tagged` / `in_category` (topic entities) and `translation_of` edges. They are derived, so they are replaced, never edited. A link resolves through its site's `SiteLinks` — every page's permalink, URL and source path, read once with `values_list`, the first page in tree order winning — built once per `index_page`, never once per link; an import shares one per site for its whole run (`one_link_index_per_site`), keeps it current as it writes (`SiteLinks.update`) and relinks, in the same transaction, the live pages whose links name what a document's page took or gave up, so a link to a page imported later resolves when that page arrives (`tests/sites/test_sync_perf.py` holds the result to the full pass and the old resolver).
- **Agent edges** (`mentions`, `about`, `similar_to`, `contradicts`, `supersedes`) come from `graph.upsert_edge`: written directly only at or above `GRAPH_EDGE_AUTO_THRESHOLD` (0.85) under a `draft`-or-higher policy, otherwise a Suggestion.
- **Behavioural edges** come from Rails' `app.user.interaction` events, aggregated into daily counts as they arrive (no reader identifier is stored) and turned into `viewed_together` edges nightly (`build_viewed_together`).
- **Vectors** live in one table, `Embedding`, for every kind of object, keyed by `(object, model)` and stamped with the `content_hash` they were computed from; a page whose hash did not change is not re-embedded. `EmbeddingField` is pgvector's `vector` on Postgres and JSON text on SQLite; kNN uses `<=>` on Postgres and computes cosine in Python elsewhere. The default embedder (`hashing-256`) is deterministic feature hashing, so everything works offline; `EMBEDDING_BACKEND=litellm` swaps in a real model, through the provider registry (`ai/providers/`).

Reading: `related(page)` merges vector neighbours (0.6) with one hop of edges and shared topics (0.4); `semantic_search`, `neighbors` (≤ 2 hops), `path` (≤ 4) and `graph_rag` (search → expand → rerank). GraphQL exposes `related`, `semanticSearch`, `graphSearch` and `entities`; REST exposes `/api/v2/graph/{neighbors,path,related,search}/`; agents get `graph.*` tools.
