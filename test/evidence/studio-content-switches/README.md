# Read the content outlets' switches against the hub's map, read-only without a credential — evidence

> **Feature:** `ZER0-049` · **Scenario:** `verify/scenarios/studio-content-switches.yml` · **Generated by:** `node verify/runner.mjs --only studio-content-switches --by agent` against `http://127.0.0.1:8017` on 2026-11-25, the app started as `verify/verify.yml` says (a fresh database, `seed_demo`, the hub's map read from `verify/fixtures/hub/`); the `stub-*` images by hand, as below

An editor who manages sites (`seed_demo` gives the demo editor `sites.manage_site`) opens Sites → Content switches. With no GitHub credential set, the section is read-only and says exactly what it needs — a fine-grained token whose repository permission "Variables" is read and write, on the three outlets. The hub map's 21 lifehacker.dev records are listed with their workflow, variable, semantics, the map's state (each verified, ✓) and auto-merge's hold (`HUB_ORIGINATION_HOLD`); every live value is "unreadable" and every effective state "unknown" — never "off" — and every toggle, "All on" and "All off" is disabled. bash-365.com and it-journey have no record in the map that day, and their variables were not read. Neither width scrolls sideways (desktop 1280 = 1280, phone 390 = 390); each table scrolls inside its own box. No console error.

## How the `stub-*` images were made

The scenario holds no credential and reaches no network, so it cannot show the preview. The `stub-*` images come from the same build and database with `ZER0_GITHUB_API` pointed at a local stub of GitHub's Actions-variables API that answers the reads with the `*_ENABLED` variables the three outlets held on 2026-11-25 (read with `gh api`) and refuses every write with a 403. A placeholder credential (not a token) was saved through the section's own form; a Playwright script opened the board and the two modals and took the screenshots, and never pressed Apply. Nothing was written to GitHub.
